## Where the time went (n = 1, one warm forward, torch profiler over the CUDA-graph replay)

The timed span of FoldForge (`model(tensors)`) does **not** contain the ESM-C language model: it runs while the input is prepared
(`models/io/dense_atoms.py::_language_features`). The kit's `fold()` span contains featurization, ESM-C and the MSA encoder, and is still faster.
The gap is therefore in trunk + sampler + heads, not in the language model's dtype or graph scope.

Sampler: 200 steps x 5 samples = ~90 % of the forward. One step before the changes took 2.43 ms (654 kernels, ~140 000 per forward):

| part of one sampler step | before | after |
|---|---|---|
| rigid motion + noise + Kabsch (torch ops, ~200 tiny kernels) | 0.45 ms | ~0.05 ms (engine glue) |
| atom encoder + decoder, 6 blocks (FoldForge-own, atom pair + rope) | ~1.3 ms | ~1.0 ms |
| token DiT, 12 blocks (engine `TokenDiTProtenix`, cuda) | 0.68 ms | 0.68 ms |

## What changed (FoldForge-owned causes)

1. `e6caadc`: `install_engine` forced `foldforge_sampler_ops = False` for every model since the 2.5.0 port, so the engine `AugmentNoise` /
   `AlignEuler` never served. Only families that realign every step use them (ESMFold2); Protenix v1 does not (0.443 -> 0.440 s at n=1). 0.542 -> 0.461 s.
2. `9d84d37`: the atom stack's conditioning projections (AdaLN scales/shifts, output gates) are the same at every step; they are made once
   per fold (`hoist_conditioning`). 0.461 -> 0.410 s.

Equality (before vs after, 5 samples, 200 steps): pLDDT mean within 4e-4 (5I28 n=1/2/4) and 8e-5 (3ptb, 1a1k); the hoist alone is bit-identical at n=2 and 4;
per-sample RMSD 0.02-0.16 A on 5I28 and 3ptb (sampler fp32 rounding; the same size as run-to-run noise between sampler paths), one 1a1k sample 1.1 A
(DNA complex); bond-length mean/std unchanged to 3 digits. CPU suite 799 passed + the new `test_atom_conditioning_hoist.py`.

## What remains (kit / FoldForge 0.76 at n = 1)

The atom blocks are ~22 kernels of 2-10 us each, ~140 us per block, 6 per step: launch-bound. The kit serves them with a fused atom block (`af`).
Other FoldForge-side items measured small (bf16 pre-cast of the atom-stack weights ~4 %, packed q/k/v/gate GEMMs ~2 %) and were not done.
Engine request (draft R22, not in the repo): a fused ESMFold2 atom block **with the atom pair** (pair LN + logits bias, 192-key window, q/k RMSNorm + rotary,
AdaLN RMS/SiLU, raw gates), i.e. what R6 asks for; the present `AtomDiT("esmfold2")` is pair-free. Also an engine API for per-fold conditioning projections.
